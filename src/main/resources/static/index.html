1. Connections

Passwords are never logged. They are written to disk only if you tick "save the password", and then encrypted (AES-256-GCM) in ~/.dbmerge/. Remembered connections without a saved password come back locked.

2. Phase 1 — compare DDL

Tick two or more connections. Every database is compared with every other; sources are opened read-only.

Undeclared references

Finds columns that act like foreign keys but have no FOREIGN KEY constraint. The merge cannot rewrite those when a parent row is re-keyed, so check a schema here before merging it. Read-only.

The data check runs one read-only join query per finding (60 s timeout each, at most 1,000). On a large production schema, run it on a copy or off-hours.

3. Phase 2 — compare data

Pick the business key per table (default: primary key). Pick a natural key such as e-mail or SKU when ids were assigned independently in each database. Row data is read-only.

4. Phase 3 — merge into a master

The master is the only database that can ever be written. Every other selected database is read-only. A dry run changes nothing: it produces the full SQL script and a preview report. Take a Data Pump backup of the master before executing.
